# Decision Matrix

One row per component/check. Choice is justified by empirical measurements from both projects, with auditability, determinism, and maintenance trade-offs stated honestly.

| Project | Component / Check | Choice (rule / statistical / LLM / hybrid) | Justifying Measurement | Trade-offs & Engineering Justification |
| :---: | :--- | :---: | :--- | :--- |
| **A** | Plain-language parsing: fact extraction from free text | **LLM** | **89% exact** on 28 complete descriptions (English, Hinglish, Hindi) vs **25%** for regex baseline; 0 invented fields; ~4.9s latency, ~$0.13/1k requests (Gemini Flash). | Not strictly deterministic across model updates; requires external API call / network boundary; personal salary text is processed by LLM. |
| **A** | Plain-language parsing: ask-or-proceed decision | **rule** | Rules stopped **2 LLM hallucinated guesses** (invented age=60 from "senior citizen", assumed monthly pay without cue) and cut unneeded questions from 22 down to 2. | Rules only catch known ambiguity patterns; requires expanding edge-case guards from real user traffic over time. |
| **A** | Tax computation (slabs, deductions, 87A, surcharge with marginal relief, cess, rounding) | **rule** (code + YAML per FY) | **100% (494/494 cases) rupee-exact**, 100% deterministic over 10 repeats, **0.1 ms latency**, **$0 cost**, 100% trace completeness. | Requires updating YAML config on new budgets; logic correctness requires independent test oracle verification. |
| **A** | Tax computation by LLM at query time | **not shipped** | **25% (3/12 cases) exact**; **9 silent failures (0 loud errors)**; 20.0s latency; $0.54/1k requests; only 55% of trace checks pass. | Zero code maintenance, but dangerously unreliable: fails silently on non-linear step functions (marginal relief, surcharges). Unacceptable for financial compliance. |
| **A** | Tax computation by LLM-compiled rules | **not shipped as pipeline** | Raw LLM compile: **0% exact (crashed)**; post-crash fix: **24% exact (194/256 silent failures)** with 17 critical defects (e.g. 10% surcharge on >5L, inverted 87A). Recompile for FY25 produced a different buggy program. | Runtime matches hand rules once reviewed, but risk shifts entirely to human code review. High maintenance overhead without runtime advantage. |
| **A** | Regime recommendation & explanation | **rule** (template over exact totals) | Exact arithmetic on two deterministic totals (`min(old, new)`, tie $\to$ new); template generated in microseconds with zero hallucination risk. | Explanations are templated rather than conversational; converting to LLM generation would introduce numbers-mismatch risk. |
| **A** | Absorbing the next Budget change | **hybrid: human + LLM assist** | Hand rules absorbed FY 2025-26 in **26 YAML lines and 0 code lines**, passing 238/238 cases. Partial updates caused 65–150 silent errors, caught by threshold boundary tests. LLM may propose YAML diffs, but human + boundary suite gates release. | Requires human sign-off and independent oracle updates on each Budget release. |
| **B** | a. Renamed or dropped column | **rule** | Rules: **1.00 detection, 0.00% FA**, 25M rows/s. Stats: 1.00. LLM: 0.50. | Exact schema set diff is instantaneous and auditable; requires maintaining schema definition per customer. |
| **B** | b. Column type change | **rule** | Rules: **1.00 detection, 0.00% FA**, 5.2M rows/s. Stats: 1.00. LLM: 0.50. | Fast dtype validation; schema must be defined upfront. |
| **B** | c. Date format switch | **rule** | Rules: **1.00 detection, 0.00% FA**, 376k rows/s. Stats: 1.00. LLM: 0.00. | Regex enforces explicit date contract; stats version only flags "unusual text shape". |
| **B** | d. Lat/Lon swapped | **rule** | Rules: **1.00 detection, 0.00% FA**, 1.0M rows/s. Stats: 1.00. LLM: 0.70. | Bounding box is NYC-specific; stats version (Mahalanobis distance) generalizes better across cities without hardcoded coordinates. |
| **B** | e. Exact duplicates | **rule** | Rules: **1.00 detection, 0.00% FA**, 539k rows/s. Stats: 1.00. LLM: 0.06. | Exact hash deduplication is $O(N)$ and cheapest. |
| **B** | f. Near-duplicates | **rule (+ stats)** | Rules: **1.00 detection, 0.05% FA** vs Stats: 0.87 detection, 0.10% FA. | Keyed blocking rule (agency/type/address within 5 min) is fast but brittle to typos; stats fuzzy matching catches typos but is slower. |
| **B** | g. Null spike per agency | **statistical** | Stats: **1.00 detection, 0.00% FA** with learned per-agency baselines. Fixed rule threshold (30%) either misses subtle spikes or flags naturally sparse agencies. | Requires maintaining learned distribution per agency; must refit periodically. |
| **B** | h. Closed date < Created date | **rule** | Rules: **1.00 detection, 0.00% FA**, 440k rows/s. Real data has 331 true violations. | Strict invariant check; zero false alarms. |
| **B** | i. ZIP inconsistent with borough | **rule** | Rules: **1.00 detection, 0.00% FA**, 471k rows/s. Stats: 1.00. LLM: 0.10. | Prefix range table is deterministic for NYC; learned conditional probability $P(\text{borough} \vert \text{ZIP})$ is needed for unseen jurisdictions. |
| **B** | j. Complaint Type vs Descriptor | **statistical** | Stats: **0.99 detection, 0.18% FA** via learned co-occurrence matrix. LLM detection was only 0.10. | Learned frequency matrix handles distribution gracefully; novel valid municipal pairings trigger false alarms until retrained. |
| **B** | k. Resolution vs Status contradiction | **rule + LLM annotate** | Keyword rules: **1.00 detection on injections, 2.45% FA on clean data**. LLM alone: 0.35 detection. Stats classifier: 0.02. | Keyword rules are high-recall but flag nuanced text ("investigation closed, pending contractor"). LLM is best used to annotate flagged rows, not veto. |
| **B** | l. Personal data (PII) in free text | **rule (regex)** | Rules: **1.00 detection, 0.45% FA**, 63k rows/s. Stats: 0.00. LLM: 0.30 detection. | Regex catches structured PII (phone/email); uncontextualized person names require NLP/LLM review. |
| **B** | Hybrid pipeline orchestration | **hybrid** | Rules + stats alone: **~6,800 rows/s**, ~$0.002/M rows compute. With LLM verify-and-drop (veto): semantic detection collapsed from **0.99 $\to$ 0.08** (LLM incorrectly dismissed 146/150 true alerts) and throughput fell to 44 rows/s. Veto disabled by default. | Tier 1 (Rules on all rows) + Tier 2 (Batch stats) + Tier 3 (LLM annotating flagged rows or 1–2% audit sample). Balances cost, throughput, and accuracy. |
